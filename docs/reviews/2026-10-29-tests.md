## Quality of the new tests

- **A5–A8 (`provider-requests`, `scheduler`, `speech`, `deadlines`, `live-tape`):**
  - These are behavioural tests with a fake clock and deferred promises. Every mutation was caught. Good.
  - `live-tape` replays 20 real Gemini outputs and 1 OpenAI output through today's validator. That is useful as a false-rejection canary.
- **C6 (`tell-cue`, 8 tests):** behavioural. Only the redundant guards above are untested.
- **C7 (`spatial-objection`, 2 tests):** these are thin, and partly unrealistic.
  - Test 1 builds a state in which only `E_KETTLE_COLD` is known for O11. That state cannot happen in play: `PinchObject O11` collects all **3** O11 memories at once, so a real kettle drop always returns `[]`.
  - In the hero case, the only breaker-holding object a player can objection-drop on directly is **O12**. Every other breaker needs the wallet (scratch probe `probes/breakers.ts`). The decision log documents this as intentional, but no test documents the consequence.
  - Test 2 pins the constant `[80,0,-125]`.
- **D1 (`clue-presentation`, 5 tests):** these test real boundaries: privacy, observation gating, clockwise order, crossing off only after the facts are known, and replay. Two weaknesses:
  - The tie case is missing.
  - The replay test reuses the already reordered graph (see P2-3).
- **A2/A3 (`review-safety`):** good probe coverage, with each probe asserting a specific code (`FORBIDDEN`/`POLARITY`). The weakness is that there is only **one** benign-phrasing test. Scratch probe:
  - "No, Detective. I was in the Kitchen making tea at 22:30." is rejected with **POLARITY**;
  - so is "I was making tea in the Kitchen at 22:30. Nothing more to it."
  - These are natural answers that would drop to the fallback line. Nothing measures the false-rejection rate.

## Findings

### P1

**P1-1. Two A4 permission rules have no regression test.**
- **Where:** `Engine/game/Reducer.ts:22` (latest gameplay action) and `:28` (topic must match).
- **Fix:** add the two scratch tests above to `tests/game/reducer.test.ts`:
  - stale break after `PinchObject` must be rejected;
  - a break on `baseline:brooch` must not license "I lied." on `where@22:30`.

**P1-2. The Lens objection UI cannot present statement breakers. E3's `C_OKAFOR_REPLY` fix and the three `C_SEES_*` alibi breakers are unreachable in Preview.**
- **Where:** `RoomscriptSpatialObjectionController.ts:57`.
- **Fix:** either
  - list known statements (notebook claims) in the wallet, and add a pure helper such as `presentableBreakers(graph)` with a test asserting that every cover has at least one breaker reachable through the UI; or
  - remove statement breakers that cannot be presented, and let the solver verify the result.

**P1-3. Suite time is creeping up, and the long tests are still in the default run.**
- **Where:** the 1,000-player fuzz is synchronous, 26.6 s (`tests/fuzz/Players.test.ts:8`). The case fuzz is 112 s against 240 s (`FuzzCases.test.ts:40`).
- **Fixes:**
  - make a `fuzzPlayersAsync` that yields, with a sync/async equivalence test (same pattern as the case fuzz);
  - keep a 200-seed case smoke test with tight thresholds (all accepted, `maxAttempts ≤ 2`);
  - move the 5,000 cases to `npm run fuzz:cases`.

### P2

**P2-1. The secret guard's P2 items are not done, and the owner-mismatch message is unclear.**
- **Where:** `Tooling/scripts/check-secrets.mjs:14-16, 27-28`.
- **Fixes:**
  - run `sceneTokenFields` on `.prefab` and `.meta` as well as `.scene`;
  - add `\bsk-(proj-)?[A-Za-z0-9_-]{20,}`, `\bAIza[0-9A-Za-z_-]{35}` and `\beyJ[\w-]+\.eyJ[\w-]+\.[\w-]+`;
  - make the [authorization-header redacted] case-sensitive and require a token after it: `\bBearer [A-Za-z0-9._~+/-]{16,}`;
  - first call `git rev-parse --git-dir` with `stdio:"pipe"`; on failure print "git refused this repository (not a repo, or dubious ownership: use `git -c safe.directory=<root>`). Commit blocked.";
  - in the hook, use `root=$(git rev-parse --show-toplevel) || exit 1; cd "$root"`;
  - add these fixtures to `tests/tooling/secrets.test.ts`.

**P2-2. Earlier test hardening is still open.**
- **Where:**
  - golden replay fixture (M1);
  - exact solver codes (`Solver.test.ts`, broken-variant loop);
  - `llm-output.test.ts:39` → `elapsedMinutes`.
- **Fix:** same fixes as the previous review.

**P2-3. The clockwise refuter order is mutable setup state that lives outside the action log.**
- **Where:**
  - `RoomscriptEngineBridge.ts:18` sets `graph.refutation.order` from the player's pose;
  - `replayGame(createHeroCase(), log)` would then produce different refutations;
  - the D1 replay test (`clue-presentation.test.ts:11`) reuses the mutated graph, so it cannot catch this.
- **Fix:** either
  - record the order (or the setup pose) as a first `Setup` action, or
  - persist it with the tape/log, and test replay from a fresh graph.

**P2-4. The validator's false-rejection rate is untested.**
- **Where:** POLARITY trips on "No, Detective. …" and "Nothing more to it." (`LineValidator.ts:82-84`).
- **Fix:** add a benign-paraphrase corpus (about 30 lines per active account) that must all pass. Consider ignoring a leading "No," or "Nothing more" when the cited claim is positive.

**P2-5. Small gaps.**
- No tie fixture for `clockwiseRefuters`.
- No direct `tellCue` test for its truth and stale-statement guards.
- No duplicate-reference test (collision is unlikely with 64-bit aliases).
- The `spatial-objection` test uses an unreachable knowledge state; add a hero-realistic case (pinch O11 → `[]`, pinch O12 → `["E_RECORDING"]`).

**Scope reviewed:** `Engine/core`, `Engine/room`, `Engine/case` (all nine modules), `Engine/game` (all ten), the reducer's calls into `perf/FactSheetBuilder` and `perf/LineValidator`, `Content/HeroCaseHarlow1041.ts`, `HeroLineBank.ts`, `PitchLibrary.ts`, `STORY.md`, and the tests and scripts listed in the brief. `Engine/knowledge/` does not exist, so gossip (§6) is not implemented; the reducer rejects `GossipSpoken` safely.

**The async fuzz fix is sound.** `fuzzCasesAsync` (`Tooling/scripts/fuzz-cases.ts:202-209`) drives the same generator as the synchronous `fuzzCases`. It yields to the event loop with `setImmediate` after every 25 *completed* cases, so compiler inputs and order are unchanged. The equivalence test compares every field except timing. At the measured ≤55 ms per case, the longest stretch without a yield is about 1.4 s, far below Vitest's RPC timeout. The full suite now exits 0, which clears the earlier exit-1. The remaining exposure is the 120 s test timeout: 69 s under contention leaves about 1.7× margin, so a slower machine or Lens running alongside could trip it. Consider 240 s, or fewer seeds in CI with the 1000-seed run as a script.

## Verified findings

Severity is about correctness of the truth layer or of the game as designed, not hackathon priority.

### F1. HIGH: objections accept any superset of a breaker set, so lies can be broken by dumping evidence
- **Where:** `Engine/game/ObjectionJudge.ts:9-11`, which tests `breakers.some(set => set.every(id => offered.has(id)))`. The only other requirement is that each offered ref is known. Nothing caps how many refs can be offered or penalises irrelevant ones.
- **Scenario:** Pinch all 13 objects (free), ask Vale "where@22:30", then send `Object` with all 21 known refs at `C_VALE_ALIBI_0`. The objection is sustained. Repeat at `C_VALE_ALIBI_1` and it is sustained again: layer 2, 2 Hunches, **5/5 pips**. Because tells mark every cover with 100% reliability (`Reducer.ts:41`), a player never has to reason about which evidence breaks which claim. The terminal test even asserts this behaviour (`tests/player/terminal.test.ts:198`, comma-separated pair).
- **Verified:** `probe1.mts` P2.
- **Fix:** Require the offered set to equal one breaker set exactly, or allow at most N offered items (N = 1 in Lens, matching "drag evidence onto the claim"). Otherwise, charge a pip for every offered ref that is not in the matched breaker set. Add a regression test that an all-known-refs objection is overruled.

### F2. HIGH (design and fairness): "pinch everything" is a zero-minute dominant strategy with the top Holmes rating, and interrogation is never needed
- **Where:** every hero evidence item has `costMinutes:0` (`HeroCaseHarlow1041.ts:97-112`). Generated evidence is also 0 (`Dealer.ts:16`, `BeatPlanner.ts:10`). `PinchObject` charges only the maximum `costMinutes` (`Reducer.ts:117`). Scoring treats `elapsed <= max(15, minRoute*1.25)` as efficient (`Scoring.ts:8-10`), and `minRoute` is 0.
- **Scenario:** Pinch all 13 objects, file the four deductions (`E_VALE_LAMP`, `E_CABLE`, `E_KETTLE_COLD`, `E_TRUST_NOTE`, all free), then accuse. Result: **verdict correct, 0 minutes, rating 3/3**, with zero questions. The authored dramatic route (`npm run play -- --demo`: 3 objections, 75 minutes) scores **2/3**. A blind first-turn accusation also scores **2/3** (P17). Generated cases behave the same way: 6/6 sampled seeds on two fixtures were unique after pinching alone, at 0 minutes with rating 3 (P14). The player fuzz's 250 "correct" verdicts all come from the `player%4===0` policy, which pinches everything and then accuses (`fuzz-players.ts:84-87`). No fuzz player solves the case through interrogation.
- **Verified:** `probe1.mts` P1, `probe2.mts` P14 and P17.
- **Context:** `docs/decisions.md` records "free inspection means a zero case-minute minimum route" as deliberate. That decision does not address the consequences: the Three-Clue-Rule and minimum-route checks become vacuous, and scoring rewards skipping the core loop.
- **Fix (pick one):** give object memories a small cost (5 minutes), or let a pinch reveal one memory at a time, or require some routes to come from statements. Base efficiency on the *scripted* or median fair route rather than `minRoute=0`. Require deductions for rating 2 or higher. Have the solver report "routes requiring interrogation" as a design metric.

### F3. MEDIUM-HIGH (hero fairness): logically valid refutations of Vale's second lie are overruled and cost a pip
- **Where:** `HeroCaseHarlow1041.ts:116`. `C_VALE_ALIBI_1` ("Harlow was already dead") has breakers `[["E_RECORDING"],["E_CABLE","C_OKAFOR_REPLY"]]`. `E_VOICEMAIL` (line 106) proves `F_REPLY_AFTER_ARRIVAL`, `before(Vale_arrival, Harlow_death)`: the exact negation of the lie `X_DEAD_BEFORE_ARRIVAL`, `before(Harlow_death, Vale_arrival)`. `C_OKAFOR_REPLY` (line 118) asserts the same fact. The B_VOICEMAIL beat (minute 75) exists to deliver this clue.
- **Scenario:** Break layer 0, ask Okafor "about:V", then `Object [C_OKAFOR_REPLY]` → `objectionWrong(does_not_refute)`. Wait until minute 75, then `Object [E_VOICEMAIL]` → overruled again. Two pips are lost for correct reasoning.
- **Verified:** `probe1.mts` P4. The solver's `factsContradict` also returns `false` for the pair (see F4), so no check could flag the omission.
- **Fix:** Add `["E_VOICEMAIL"]` and `["C_OKAFOR_REPLY"]` as breakers, or drop `E_CABLE` from the pair. Longer term, derive valid breakers from fact contradiction (F6) instead of hand-listing them.

### F4. MEDIUM: `factsContradict` is blind to the hero's `state` schema and to all `before` orderings
- **Where:** `Engine/case/Solver.ts:247` compares `args.key`/`args.value`, but every hero `state` fact uses `args.prop` (`HeroCaseHarlow1041.ts:52-53, 57-58, 72, 91-93`). `Simulator.ts:90,92` uses `key`. `Types.ts` defines no schema, so the two authors diverged. No branch handles `before`.
- **Scenario:**
  1. `F_KETTLE_COLD` against `X_KETTLE_BOILING` → `false`.
  2. Add a second *true* fact "kettle boiling at 22:30" → `verifyCase` stays `ok:true` with no `INCONSISTENT_TRUTHS`.
  3. Mark `X_DEAD_BEFORE_ARRIVAL` true next to `F_RECORDER_ORDER` (reversed ordering) → no issue.
- **Consequences:**
  - INCONSISTENT_TRUTHS (check 8) misses these contradictions.
  - The per-layer "suspect never contradicts its own account" check misses them.
  - The B8 fuzz invariant `assertCurrentAccounts` (`fuzz-players.ts:42-50`) uses the same function. "No layer ever holds two contradictory claims" is therefore unchecked for the predicates the hero's lies actually use (kettle state and death ordering).
- **Verified:** `probe1.mts` P4 and P5, `probe2.mts` P13, `probe3.mts` (the hero INCONSISTENT_TRUTHS variant passes).
- **Fix:** Define `state` args in `Types.ts` (`{subject, prop, value}`), normalise `key`/`prop`, and handle `before(a,b)` ⟂ `before(b,a)` plus a check for transitive cycles. Add hero-based broken variants for both.

### F5. MEDIUM: the solver and the objection judge disagree on ladder topics, so the solver can certify an unbreakable lie
- **Where:** reachability (`Solver.ts:105-106`) and the LIE_UNBREAKABLE check (`Solver.ts:280-283`) require only the same speaker and `layer >= source`. `ObjectionJudge.ts:12` additionally requires `target.topic === statement.topic`.
- **Scenario:** Point `C_S1_ALIBI_0.onBreak` at a new layer-1 truth on topic `secret:S1`. `verifyCase` returns `ok:true` with `lieBreakable=2`. In play, the correct breaker `E_S1_ALIBI` gets `objectionWrong(invalid_ladder)`, costs a pip, and the cover can never break. Only the hero content test checks topic equality (`hero.test.ts:91`). Generated cases and LLM-authored content have no check.
- **Verified:** `probe2.mts` P6b.
- **Fix:** Make one shared `ladderTarget(graph, statement)` the authority for both, and add a `LIE_UNBREAKABLE` variant.

### F6. MEDIUM: lie-breakability counts breaker sets without checking that they refute the lie or are independent
- **Where:** `Solver.ts:275-279` counts distinct, reachable breaker sets.
- **Scenarios:**
  1. Set Vale's layer-0 breakers to `[["E_O2_LOCATION"],["E_O3_LOCATION"]]` (the candlestick and knife locations, irrelevant to her tea alibi) → `ok:true`, `lieBreakable=2` (P8). The player cannot deduce these "breakers".
  2. Set them to `[["E_KETTLE_COLD"],["E_KETTLE_COLD","E_VALE_LAMP"]]` → `ok:true`, `lieBreakable=2` (P7). The culprit's "two alternatives" requirement is met by a single item plus a superset of it.
- **Verified:** `probe1.mts` P7 and P8.
- **Fix:** A breaker set is valid only if the facts it proves contradict at least one false fact the cover asserts (this needs F4). Count alternatives as minimal and pairwise-disjoint by source, as `independentRoutes` already does for cards.

### F7. MEDIUM: SHORTCUT check ignores statements
- **Where:** `Solver.ts:285-288` iterates `graph.evidence` only.
- **Scenario:** A layer-0 *truth* statement by Vale asserting the victim location, three alibis and four weapon locations reduces H to 1 in a single Ask, and `verifyCase` reports **no issues** (P9b). The same content as one evidence item correctly yields `SHORTCUT`. This matters for generated or LLM-pitched cases, where each statement asserts one fact today but nothing enforces that.
- **Verified:** `probe2.mts` P9b.
- **Fix:** Run the shortcut test over every package root: evidence, truthful statements, and break-released truths.

### F8. MEDIUM-LOW: the solver ignores beat timing
- **Where:** `Solver.ts:76-79, 94-99`. Guaranteed beats are treated as fired regardless of `minute`. The reducer requires `elapsedMinutes >= beat.minute` (`Reducer.ts:48`).
- **Scenario:** Give `C_VALE_ALIBI_1` only `[["E_VOICEMAIL"]]` and set `B_VOICEMAIL.minute=999`. `verifyCase` returns `ok:true`, `lieBreakable=1`. A player who exhausts the 180-minute clock never receives the voicemail, so the lie is unbreakable.
- **Verified:** `probe4.mts` P19.
- **Fix:** Reject `minute >= clockMinutes` (BEAT_BREAKS_SOLVABILITY), and include beat minutes in min-route feasibility.

### F9. MEDIUM-LOW: lawyered (absent) suspects can still be objected against, believed and shown evidence
- **Where:** `Reducer.ts:88-125`. `Ask` (line 69) and `Press` (line 80) check `isLawyered`; `Believe`, `Object`/`CallLiar` and `RevealEvidence` do not.
- **Scenario:** Ask Vale, press 3 times (she lawyers up until minute 90, and Ask is rejected), pinch the kettle, then Object → sustained, layer 1, +1 Hunch, all while she has "walked out through your real door". The ladder breaks while she is offstage.
- **Verified:** `probe1.mts` P3.
- **Fix:** Reject these verbs while lawyered (as Ask and Press already are), or decide explicitly that objections are allowed and document it.

### F10. LOW-MEDIUM: Holmes scoring is miscalibrated (follows from F2)
- **Where:** `Scoring.ts:9-10`.
- **Scenario:** A blind first-action accusation scores 2/3 (P17). The full authored route scores 2/3. Pinch-all scores 3/3. Any session with two or more questions can never earn the efficiency point.
- **Fix:** See F2. Also gate efficiency on `deductions === required`.

### F11. LOW: Hunches give no information
- **Where:** `Hunches.ts:4-11` returns an *observed* current cover, and every observed cover already fired a `tell` event.
- **Scenario:** After breaking Vale's layer 0, `UseHunch` highlights `C_VALE_ALIBI_1`, which was already tell-flagged (P12). The design options (strike a zone or object from the grid) are not implemented, and the B4 claim that Hunches use player-knowledge solver mode is not met.
- **Fix:** Make a Hunch strike one solver-eliminable-but-unobserved card, or reveal which offered breaker class works.

### F12. LOW: a topic override masks later-layer statements on the same topic, making reachability order-dependent
- **Where:** `Actions.ts:11-14`. Overrides are applied after the layer scan and never expire.
- **Scenario:** Add a layer-1 truth on Vale's `baseline:brooch`. If the player breaks the baseline first and the alibi second, that statement never becomes current (P16). The solver counts it as reachable through the layer-1 unlock and reports `ok:true`. The hero and generator are not affected today, because baseline topics have only layer 0.
- **Fix:** Apply an override only while `ss.layer` equals the override's layer, or have the solver reject replacement topics that also carry higher layers.

### F13. LOW: `localeCompare` in solver tie-breaks
- **Where:** `Solver.ts:167, 229`.
- **Scenario:** Node/ICU and code-unit orders differ on engine IDs: `"E_O2,…" < "E2"` under ICU, and the reverse by code unit (P20). `minRouteMinutes` is unaffected because the search is exact. `minRoute` refs and package exploration order can differ between Node (tests and tapes) and a non-ICU Lens runtime. That matters if `solver.minRoute` enters a hash or a sync payload. `Affordances.compareIds` already exists for this purpose.
- **Verified:** `probe4.mts` P20.
- **Fix:** Use `compareIds`.

### F14. LOW: the hero's `roomId` does not match `roomIdentity()`
- **Where:** `HeroCaseHarlow1041.ts:29` hashes sorted `[type,index]` pairs. `RoomModel.ts:21-30` hashes `{zones, objects}`.
- **Scenario:** The hero's id is `r_27fe6e25`; `roomIdentity(hero.room)` is `r_2bf8bfaf`. The hero `caseId` embeds the former, so anything that recomputes the room id (sync `CaseInit`, room re-binding) will disagree.
- **Verified:** `probe1.mts` P10.
- **Fix:** Call `roomIdentity(room)`.

### F15. LOW: `CaseCompiler` reports every exception as `ROOM_BINDING`
- **Where:** `CaseCompiler.ts:35-38`. A `TypeError` from a non-null assertion in Dealer, StatementBuilder or BeatPlanner (`!` on `find`) is returned as a non-retryable room error. Engine bugs then surface as "bad room".
- **Fix:** Catch around `simulateCase`/`bindCaseRoom` only. Let internal invariant failures throw, or report them as `COMPILER_BUG`.

### F16. LOW: free actions allow unbounded stalling
- **Where:** `Believe`, `Dismiss`, `RevealEvidence`, zero-cost `PinchObject`, `UseHunch` and `ArgumentClaim` never advance the clock (P11: 150 actions at 0 minutes, verdict still null).
- **Context:** This is documented as a fuzz-policy assumption. It is harmless in single-player Lens, but in Clue Night it lets a peer stall turn order.
- **Fix:** Optional, for Stage F: a per-turn action budget.

## Suspected or unverified (not demonstrated end-to-end)

- **S1. The Clue Night privacy model is not in the engine (Stage F).** `Suggest` stores the private refutation card in the *shared* `state.knowledge` and grid, and emits it in public `events` with only a `data.privateTo` tag (`Reducer.ts:130`). `Action.by` is validated but otherwise unused, with no roster or turn check. This is fine for single-player. It must become per-player knowledge before F.
- **S2. LLM-extracted arguments can over-credit.** `ArgumentExtracted` (`Reducer.ts:150-161`) credits any deduction whose support refs the player happens to have collected. The model chooses which claims exist, and `ArgumentClaim.span` is unused. The Holmes rating could therefore rise for points the player never argued. Truth and verdict are unaffected. A deterministic span or DeductionMatcher check is needed before E7.
- **S3. Structural culprit marker in generated motive facts.** `F_MOTIVE_*` args carry `strength`, and 3 means the culprit only (`Simulator.ts:93`, P15). Canonical text does not leak it. Any future UI or prompt that prints fact args would.
- **S4. ES and Lens compatibility of the D5 modules is unverified.** The handoff states the generator and harvested tape have not had a post-pause `RecompileTypeScriptTool` pass. Engine code uses only ES2019-2020 features (`flatMap`, `?.`, `??`, optional `catch` binding), compiled for es2021, and no Node APIs, `Math.random`, `Date.now` or `structuredClone` appear in `Engine/` or `Content/`. Lens compilation of `Engine/case/*` should still be confirmed.
- **S5. Pressure beats can fire after a timeout in the same pass.** The post-action beat loop (`Reducer.ts:186`) checks `verdict===null` once before iterating. A `pressureMinutes` beat that times the game out lets later guaranteed beats in the array still fire. The effect is cosmetic: events only, no truth change.
- **S6. Solver reachability ignores that a cover stops being current once its suspect's layer passes its topic.** This only bites with multi-topic ladders (see F12). The hero and generator are unaffected today.

## What is solid

- **Deterministic core.** sfc32 with non-consuming named forks, UTF-8 FNV-1a checked against published vectors, and fail-closed canonical JSON (rejects undefined, NaN, cycles, sparse arrays, non-plain objects). No `Math.random`, `Date.now`, `Intl` or Node APIs in `Engine/` or `Content/`. The only order leak is `localeCompare` (F13).
- **Truth boundary in the reducer.**
  - `learnFact` admits only `truth:true` facts.
  - Cover statements never leak their facts.
  - `LlmOutput` is audit-only and returns before any gameplay path.
  - `LineSpoken` touches only `saidSoFar` and `recentLines` after seven-gate validation.
  - Confession requires the engine's correct verdict and the culprit.
  - `PitchReceived` is inert.
  - The graph is never mutated (fuzz-checked).
- **Sequencing.** A contiguous host `seq` is enforced by throwing, and replay is exact.
- **Objection gating.** The claim must be current and observed, and every offered ref must already be known. The cover leaves the current set after it breaks, so Hunches cannot be farmed (fuzz-checked). Baseline corrections cannot skip Vale's murder ladder.
- **Refutation.** It is tuple-conditional: the card's fact must actually contradict the suggestion. Suspects refute only from current truthful accounts. The grid uses only observed facts, never the envelope.
- **Solver core logic.**
  - `consistent()` is per-fact and monotone, so union-of-packages elimination is exact.
  - Source-disjoint independent routes are searched completely.
  - A circular-breaker guard disables the edge under test.
  - The branch-and-bound minimum route is exact under a monotone cost.
  - Beats are checked individually; because consistency is monotone, that is sufficient.
  - Per-layer self-consistency includes replacement variants.
- **Hero content.**
  - The envelope is unique.
  - Every non-envelope card has two genuinely disjoint routes (the lamp and the mug are independent victim sources; object and witness sources exist for each alibi and weapon).
  - The baseline lie is separated from the ladder.
  - The line bank cannot leak the next layer or the confession.
- **Generator.**
  - Model output cannot set truth: the closed pitch schema rejects unknown fields, and the culprit comes from the seed.
  - Repair is restricted to exact-path patches.
  - Compilation is deterministic and passes 5000/5000.

## Top 5 fixes, in priority order

1. **Tighten objection judging (F1, F9).** Require an exact breaker-set match or a single dragged item, and reject verbs against lawyered suspects. Add regression tests for the all-refs dump and the absent-suspect objection.
2. **Make the core loop matter (F2, F10).** Give object memories a cost or limit them per pinch, recalibrate Holmes efficiency against a fair route instead of `minRoute=0`, and require deductions for higher ratings. Then re-run the player fuzz with an interrogation-only policy that must still be able to win.
3. **Fix contradiction semantics (F4, then F6).** Use one typed `state` schema (`prop`), handle `before` reversal, and derive or validate breakers by actual contradiction with the cover's false facts and by source independence. Add hero-based broken variants.
4. **Repair the hero's Vale layer-1 breakers (F3).** Accept `E_VOICEMAIL` and `C_OKAFOR_REPLY` on their own, and add a test that every evidence item proving the negation of a lie's false fact is accepted as a breaker.
5. **Close the solver/reducer model gaps (F5, F7, F8, F12).** Use one shared ladder-target rule including topic, run the shortcut check over statements, enforce beat minutes against the clock, and keep overrides from masking higher layers. Each needs a broken variant, ideally built on the hero rather than the 2×2 fixture.

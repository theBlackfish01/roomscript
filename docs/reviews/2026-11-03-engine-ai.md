# Roomscript review, fourth pass: engine correctness and AI quality (2026-11-03)

**Scope:** whether the 10-29 P0/P1 fixes hold, plus new bugs in the third-pass code (`5923208..c343bb8`: D3, D2, D6, validator v3, cheap questions, rating/par). It also proposes how to fix speech variety and audio reliability for the video.

**Read-only.** Nothing in the repo was edited. I made no git writes, no Lens MCP calls, no paid API calls, and opened no secret files.

**Probes** live in `<local-development-path>`, each with an `.out.txt` beside it. They run with `Tooling\node_modules\.bin\tsx`.

## Verdict

**The engine work is sound.**
- Every engine P0/P1 from 10-29 is fixed or reduced to a design residue. Scoring now needs the player's knowledge to pin down a single hypothesis. Arguments must match a support set exactly. The heard alibi is required. Timeout allows exactly one accusation. The setup pose is a logged first action, and replay is byte-identical.
- I found no new truth-rule violations in D3, D2 or the new reducer paths.

**The AI safety layer is much stronger on the old attack corpus but has a new hole.**
- Of the 71 lines that got past the validator on 10-29, 70 are now rejected. The 71st is a superscript-digit line that the validator normalises to the same 22:30, so it is harmless.
- **New gap (P1): role and participant swaps pass.** For example, "Vale intended to expose Harlow's forged trust accounts" is accepted as Pike's motive line. Prompt v3 explicitly asks the model to "change its word order", which invites exactly this kind of swap.
- The negative-canonical polarity flip from 10-29 (N4) is still open.

**The real problem for judges is presentation, not safety.**
- **P0 for the video: the saved scene has `stageMode: true`, and in Stage mode every suspect is silent.** `RoomscriptTts` throws `unavailable` when offline, so the result is captions only.
- In live mode:
  - 12 of 30 study calls had no audio. Of the 28 live calls, 10 played subtitle-only.
  - 18 of 27 accepted model lines repeat the canonical sentence word for word.
  - The authored line bank is literally the 46 canonical sentences.
- The validator is not what makes production speech dull: Gemini barely paraphrases, and the production study saw only 1 rejection in 28. As soon as the model is given real personality, the false-rejection rate will climb toward the surrogate study's 53%.

**The fix for both problems is the same:** make the suspects' speech a finite, authored-offline, pre-validated and pre-voiced set, and have the live model choose and assemble from it (WP-1 to WP-4).

## 2. New findings

### P0 (presentation)

**P0-1. The shipped and saved configuration has silent suspects.**
- **Where:**
  - `Assets/Scene.scene:854` has `stageMode: true`.
  - `RoomscriptTts.ts:32` and `:54` return 0 or throw `unavailable` when `client.isOffline()`.
  - `AnswerPipeline.ts:103` always takes `fallback()`, which uses the canonical bank.
- **Effect:** in Stage mode, every answer is a captioned recitation of the canonical sentence with no voice and a still jaw. Any take recorded in the saved configuration has no dialogue audio.
- **Fix:** WP-2 (bundled audio) makes Stage mode fully voiced. Until then, record takes in live mode with fresh RSG tokens.

### P1

**P1-1. One transient provider error permanently turns off live dialogue for the session.**
- **Where:** `Engine/ai/Degradation.ts:8-13`, `ProviderRequests.ts:30`, `RoomscriptInterrogationController.ts:92`.
- **Repro (`a2_degrade`):** these errors all map to `unavailable`, which drops the level to 1 ("Prepared questions") with `preferAuthored=true`:
  - a Gemini 503 "model is overloaded" (UNAVAILABLE);
  - a 500 INTERNAL;
  - a network error string.

  A single 429 drops it to level 2. `success()` never raises the level, and once `preferAuthored` is set the model is never called again, so it can't recover. The downgrade happens even when the same question's gpt-4o-mini retry succeeds.
- **Why it matters:** Gemini 2.5 Flash 503s are common. In a recording session, the first hiccup silently switches the rest of the take to recitations.
- **Fix:**
  - Downgrade only on question-level failures, i.e. the final origin was not `model`, and only after 2–3 consecutive ones.
  - Treat 5xx and network errors as transient.
  - Retry level 3 after 60 s, or on every Nth question.
  - Add a "Reconnect" chip.
  - Tests:
    - one 503 followed by a successful fallback keeps level 3;
    - three consecutive question failures give level 2;
    - recovery after the cooldown.

**P1-2. Validator v3 accepts role and participant swaps that invert the meaning of a claim.**
- **Where:**
  - `LineValidator.ts:92-102` (a bag-of-words ratio);
  - `:131-133` (participant order is checked only around "answer" verbs);
  - `Prompts.ts:14` ("change its word order").
- **Repro (`a1_roles`):** all of these pass in answer mode with the correct cite.

| Suspect | Canonical | Passing line |
|---|---|---|
| Pike `C_PIKE_TRUST` | "Harlow intended to expose Vale's forged trust accounts." | "**Vale** intended to expose **Harlow's** forged trust accounts." (motive inverted) |
| Vale, layer 2 | "…The cable was in my hands." | "Harlow met me in the Study at 22:30. The cable was in **his** hands." (means moved to the victim) |
| Vale, layer 1 | "I reached the Study at 22:30. Harlow was already dead." | "Harlow reached the Study at 22:30. I was already dead to him." |
| Witness `C_SEES_S1` | "I saw Imran in the Hall at 22:30." | "**Imran saw me** in the Hall at 22:30." (moves the speaker into the Hall) |
| Witness `C_SEES_S3` | "I saw Okafor in the Kitchen at 22:30." | "Okafor saw me in the Kitchen at 22:30." (same) |

- **Why P1:** these are card/speech mismatches about truth. The filed card says one thing and the suspect says the opposite. That is the exact property C5 exists to guarantee. The prompt instruction makes an accidental swap plausible, not just an adversarial one. How often it happens in production is *suspected* low, since Gemini mostly recites.
- **Fix:**
  - Short term:
    - add role n-gram checks: every `(Name|I|my|me) + verb` and `(Name's|my|his|her) + noun` bigram in the canonical must appear in the line, after the stem map;
    - forbid possessive or pronoun substitutions (`my`↔`his`↔`her`, `I`↔`me`) unless the canonical contains that form;
    - remove "change its word order" from the prompt.
  - Proper: WP-1 and WP-3, which remove free-text claims from the shipped path.

**P1-3. Negative-canonical polarity flips still pass (10-29 N4).**
- **Where:** `LineValidator.ts:88-90`. Polarity is a negator-presence boolean on `claimWords(text)`.
- **Repro:** for layer-1 press, the canonical is "Harlow never spoke after I entered the Study." These pass:
  - "Harlow spoke after I entered the Study, never doubt it."
  - "Harlow spoke after I entered the Study. **No.**"

  Either one has Vale state the hidden truth while still at the lying layer.
- **Fix:** match the negator to its verb. The canonical's negated verb stem must appear with the same negator immediately before it ("never spoke"). Reject a negator token anywhere else in the line unless it is part of a closed discourse phrase. Add the two lines as fixtures.

**P1-4. Live audio fails structurally, not just under precache contention.**
- **Evidence:** `Tooling/results/production-study-2026-10-30.json`. Audio minus text, for a single sentence, is 2.2–3.4 s.
- Three of the 17 uncached-condition calls got no audio: samples 25, 27 and 28 (Pike, 1 sentence, text 2.0–2.9 s). TTS overran its `min(4000, 6500−text)` budget with nothing precaching. During precache, only 3 of 10 calls got audio.
- **Fix:** WP-2 and WP-3. In short:
  - every line the game can say is pre-voiced;
  - live TTS remains only for model-improvised deflections, with a bundled per-suspect filler covering the wait;
  - precache is dropped.

### P2

1. **The bank and filler are not in character.**
   - The filler "Let me think." fires at 600 ms before almost every live answer.
   - It is admitted as a `LineSpoken` with `none`, so it fills one of the two `recentLines` slots (`FactSheetBuilder.ts:20`).
   - The bank has a separate, unused filler: "Give me a moment to collect myself."
   - **Fix:** use per-suspect bundled fillers at 1000–1200 ms (WP-2), and exclude lines citing `none` from `recentLines`.
2. **The `claimWords` closed-phrase list (`LineValidator.ts:20`) is fitted to the first corpus.** It contains whole sentences from that corpus, such as "you may examine them if it helps you sleep". So the first-corpus 11/69 (15.9%) is an in-sample figure; only the holdout 18/34 (53%) is a real estimate. Don't keep growing this list. Replace it with WP-3's register vocabulary.
3. **SetupCase residuals:**
   - On any generated case, `reduceGame(SetupCase)` throws `Missing claimed mark for S1` (`e2_gen`), because `refuterMarks` still hard-codes `where@` (`CluePresentation.ts:7`). This is the 10-29 N6 bug, now inside the reducer. It's harmless while only the hero ships.
   - An invalid setup uses up seq 1, so a corrected setup is rejected with `invalid_setup` (`Reducer.ts:84`), and the order silently falls back to the graph default. Engine and sweep stay consistent, because both read `state.refuterOrder`. Allow setup while `lastSeq===1` and the previous action was a rejected setup, or validate the pose in the bridge before dispatching.
4. **Hunch farming.** The four baseline lies, at 5 minutes each plus their pinches, give 4 hunches by minute 60 (`e1`). Hunches are still low-value (F11), so this is harmless, but one objection per suspect could grant them instead.
5. **The unrefuted oracle** (see N1 above). Author one decoy tuple that nobody can refute until a layer-1 truth is unlocked, so the "not proof" text is honest. Or make Suggest unavailable until some evidence has been gathered.
6. **"File known proof" (`RoomscriptClosingController.ts:23`) auto-files `availableArguments`.** Deductions take no skill: the exact-set rule from N5 is enforced, but the player never chooses. For the closing beat, show the four deduction cards and have the player attach one held card to each, still exact-set. Even a single tap per card makes the 2nd star feel earned, and reads well on video.
7. **The opening polls `engine.snapshot()` every frame in the `ready` phase** (`RoomscriptOpeningController.ts:61`). The state is about 8 KB and a clone takes about 0.12 ms on the PC, so this is cheap and *not* the cause of the Preview stalls. Still, cache the verdict from `onState`.
8. **Leftovers:** the shared cooldown (N6); no hedging (N9); a 2000-character question; production Tape in RECORD mode; the [authorization-header redacted] false positive; deflection-mode lines can still use accented spellings of names ("ask imrán about the cáble"), because the paraphrase gate doesn't run on deflections. Add the ASCII allowlist after NFKD.

## 3. Speech-variety design

**The constraint.** Bag-of-words fidelity checking and free, characterful speech pull against each other:
- Every persona tail ("I trust that will suffice", "Write it down slowly if you like") adds content words that the canonical doesn't contain.
- Every loosening (bigger stopword lists, a lower ratio) widens the role-swap hole from P1-2.

**The answer.** Don't validate free prose at runtime for factual lines. Separate the claim (finite, authored offline, judged, frozen) from the performance (choice, tone, register), and let the live model direct rather than write.

### Option comparison

| Option | Variety | Safety | Latency | Verdict |
|---|---|---|---|---|
| Loosen v3: register words, lower ratio | Medium | Worse (P1-2 widens) | Unchanged, 2–5 s | No |
| Second-chance repair call on rejection | Medium | Same | +1.5–2.5 s on about 50% of lines, which breaks the audio budget | Only offline |
| Key-token semantic check (v4, WP-3) | Medium-high | OK if role n-grams are included | Unchanged | Yes, for the residual free-text path |
| **Offline variant bank + register segments, cache-first (WP-1)** | High, curated | Strongest: every line is judged by model and human before commit | 0 ms text, 0 ms audio | **Yes, core** |
| **Live model as selector/director over the bank (WP-1b)** | High, responsive to the question | Safe by construction: enum output | Probably ~1.2–2 s text, 0 ms audio (*suspected*; measure in Preview) | **Yes, keeps "live AI"** |

### WP-1. Authored variant and register banks (Claude-generated offline, validated, committed)

**Goal:** each suspect gets 4–6 voiced paraphrases per statement and mode, plus a per-suspect register of openers, tails, fillers, deflections and lawyered lines. Selection is deterministic and depends on mood.

**Files:**
- New: `Tooling/scripts/generate-variants.ts`. It reuses the red-team harness's `.env` loading, cost ledger and sanitising.
- Output:
  - `Tooling/results/variants-<date>.json`, the raw run with provenance;
  - generated `Assets/Scripts/Content/HeroVariantBank.ts`.
- Changed:
  - `Engine/core/Types.ts`: `LineBankEntry` gains `variant`, `emotionTag` and `segments`;
  - `Engine/perf/LineBank.ts`: `lookupLine` picks a variant by `hash(caseId, seq, suspect, topic)`, skips `recentLines`, and is weighted by `mood.emotion`, so composure 1 picks `rattled` variants;
  - `Content/HeroLineBank.ts` merges the banks.

**Generation:**
- For each current-account statement in modes answer, press and broken (46 unique lines today):
  - generate 10 candidates with persona, acting notes, era and a short style card;
  - require the candidates to keep every name, time and the role order.
- **Filters:**
  1. `validateLine` at the *current strictness*. Don't loosen the validator to fit the bank.
  2. The P1-2 role n-gram check.
  3. An independent model judge: same facts, participants and polarity, no new assertion about people, places, times, habits or interactions.
  4. Wadood skims every line on the hero video path, about 40 lines.
- Keep 4–6 per entry.
- **Register segments, per suspect:**
  - 6 openers ("No, Detective.", "Really.");
  - 8 assertion-free tails ("I trust that will suffice." for Vale; "Write it down slowly if you like." for Imran);
  - 3 fillers, including a non-verbal "Hm.";
  - 8 in-character deflections and 3 lawyered lines.
- Segments must pass a new `assertionFree` gate: no gazetteer entity, time, number, person or location noun, victim state, negation, or forbidden token, and no content word from *any* case canonical. Each segment is its own sentence, so it lines up with the audio clips.
- **Cost:** about 150 generate calls plus about 150 judge calls. Using the red-team ledger rates, estimate $5–10.

**Runtime:**
- A line is `[opener?] + claimVariant + [tail?]`.
- `validateLine` accepts the composed line if the claim segment is exactly a bank variant for the cited ref and mode, and every other segment is exactly a register entry for that suspect. Membership is checked instead of the ratio.
- The engine reducer's re-validation in `LineSpoken` uses the same membership rule, so authority stays in the engine.

**Acceptance:**
- A unit test proves every bank variant and every composition passes `validateLine`.
- Every register segment passes `assertionFree`.
- No variant passes for a different ref.
- Replay is deterministic.
- In a 12-question hero run, no line repeats within 3 turns per suspect.

### WP-1b. Live model as director (selector schema)

**Goal:** keep a genuinely live, question-responsive AI beat, with output that is safe and pre-voiced.

**Files:** `Engine/perf/AnswerSchema.ts` (new `buildDirectorSchema`), `Engine/ai/Prompts.ts` (prompt `roomscript-direct-v1`), `Engine/ai/AnswerPipeline.ts`, tests.

**Schema** for a mapped, locked topic:
```
{ variant: enum[ids for this ref+mode],
  opener: enum[ids|none],
  tail: enum[ids|none],
  emotion }
```
The model reads the free question and the persona and picks a tone: a hostile question gets the irritated variant and a sharp tail. Unmapped topics keep the current deflection prose path, or pick from the deflection enum.

- Output is about 30 tokens.
- Text latency is *suspected* to be about 1.2–2 s. Measure 20 calls with the existing `RoomscriptProductionStudyLeafScenario`.
- Audio is 0 ms, because every option is bundled (WP-2).
- An invalid enum can't happen with a strict schema. If it does, the deterministic WP-1 choice is used.

**Acceptance:**
- A pipeline test: a mocked director reply maps to a composed answer that the reducer admits.
- The production LEAF reaches **audio ≥ 27/28** and **first audio p95 ≤ 3 s**.
- `INTERROGATION|` logs show variety, with distinct line IDs ≥ 60% across 8 phrasings.

### WP-3. Validator v4 for the remaining free-text path (deflections and an optional "improv" flag)

**Goal:** better recall without the P1-2 hole.

**Files:** `Engine/perf/LineValidator.ts`, `tests/perf/review-safety.test.ts`, and `Tooling/scripts/validator-redteam.ts` (rescoring only, no API spend).

**Rule:** a line passes if:
1. every key token of the canonical (entities, times, the main verb stem, a negator+verb bigram, and role bigrams) is present;
2. every other content word belongs to the canonical vocabulary, the suspect's register vocabulary (derived from the WP-1 segments) or a closed discourse list;
3. there is no new entity, number, time, person noun or victim state, and no negator outside a closed phrase.

Then delete the fitted sentence list at `LineValidator.ts:20`.

**Acceptance:**
- Using `npm run redteam -- --revalidate` on both saved corpora, with no API cost:
  - attacks still 0/96 and 0/48;
  - holdout false rejections ≤ 25% (from 53%).
- All P1-2 and P1-3 lines become rejections.
- The 10-29 probe corpus is unchanged: 0 real bypasses.

## 4. Audio-reliability design

**Can RSG TTS output be saved? No, not from the Lens.**
- `OpenAI.speech` (RSG `HostedExternal/OpenAI.ts:186-214`) turns `resp.asResource()` into an `AudioTrackAsset` through `RemoteMediaModule`.
- `RemoteApiResponse` exposes only `asResource()`, `statusCode`, `metadata`, `body: string` and `uriResources` (`Support/StudioLib.d.ts:16166`). There are no bytes.
- Lens has no file write, and I found no on-disk RSG audio cache. The 18 `%TEMP%\*.tmp.wav` files are an unrelated app's daily sounds.

So pre-voicing has to happen outside the Lens.

**Options for offline voices:**

| Option | Key | Voice match with the live path | Cost / licence |
|---|---|---|---|
| **OpenAI `/v1/audio/speech`, `gpt-4o-mini-tts`, same voices (coral/ash/sage/echo), per-line `instructions` from acting notes + emotion.** Recommended. | Needs a **new OpenAI key** from Wadood in `Tooling/.env`. Only an Anthropic key exists today; `check-secrets` already blocks `sk-`. | Identical model and voices, so bundled and live lines sound the same. | Third-party estimates put it at about $0.015 per minute of audio. About 420 clips (~20 min) costs under $1, even with 2 takes. OpenAI's usage policy **requires telling users the voice is AI-generated**: add this to the Devpost text, README and an in-lens credits line. OpenAI also marks `gpt-4o-mini-tts` as deprecated, shutting down 2027-01-06. Bundling insulates the submission from that. |
| Kokoro-82M, local, Apache-2.0 | None | Different voices from live RSG, so only acceptable if *all* speech is bundled (Stage mode plus director) | Free |
| Recording the Preview audio output during a live session | None | Same | Only for the video, not shipped |

**Size:** about 420 clips (46 lines × ~6 variants, plus register segments and narration) is about 20 minutes. Mono MP3 at 32–48 kbps is about 5–7 MB. Snap's publishing page gives 25 MB as the Spectacles maximum, while the Lens Studio project settings page still says 8 MB. Confirm which one Lens Studio enforces before relying on 25 MB; at 32 kbps the bank also fits under 8 MB.

### WP-2. Bundled voice library

**Files:**
- `Tooling/scripts/render-voices.ts` reads the WP-1 bank, register and narration. For each `voice|sentence` it calls OpenAI TTS (mp3, then ffmpeg loudnorm to −16 LUFS, mono, 24 kHz, 40 kbps). It writes `Assets/Audio/Voice/<suspect>/<sha1>.mp3` and a manifest `Assets/Scripts/Content/VoiceManifest.ts` (key → index), and records cost in the ledger.
- New `RoomscriptVoiceLibrary.ts` with `@input clips: AudioTrackAsset[]`, wired once through VirtualScene in manifest order. A LEAF check asserts the count and order.
- Fallback: `requireAsset` per clip, if that works for imported audio. *Suspected* to work, since RSG uses `requireAsset` for its own assets; verify with one clip first.
- In `RoomscriptTts.synthesize`, look in the library first, with the key normalised exactly like `splitSentences`. Use RSG only for misses.
- Remove `precacheCurrent` from `selectSuspect`, or make it `speculative` and limit it to misses.
- Stage mode plays bundled audio, so P0-1 is solved.

**Narrator:** voice the opening captions ("Listen at the door.", "Nobody leaves.", "Edmund Harlow was found at 22:41. Four guests. One killer.") and the WREN/result lines with a fifth voice. This is the cheapest big win for the video.

**Acceptance:**
- Strict LEAF in Stage mode: every hero-path line starts audio within 2 frames of admission, jaw amplitude max > 0.3, and no `TTS|subtitle_fallback`.
- The live production LEAF: audio ≥ 27/28.
- The size budget is recorded in PROGRESS.

### WP-4. Live-path hardening, for improvised deflections only

- **P1-1** degradation fix, with tests.
- **Scheduler:**
  - the cooldown is per provider and per kind (N6);
  - live TTS for sentence 1 jumps the queue;
  - background work never takes the last two slots while a question is in flight.
- **Hedging:** start gpt-4o-mini at about 2.3 s if Gemini hasn't answered (N9).
- **Budgets:** start sentence 2's budget when sentence 1's audio starts; a failed continuation should skip that sentence and keep going, not abort.
- **Filler:** a bundled per-suspect filler at 1000–1200 ms, never in `recentLines`.
- **Prompt:** a first sentence of 10 words or fewer for improvised lines. RSG offers no streaming TTS: `performApiRequest` returns the whole file, *suspected* from the package code.
- Pass `actingNotes` + emotion as the TTS `instructions` (N12).

**Acceptance:**
- Unit tests for each item.
- Rerunning `probe-pipeline`: a Gemini 429 no longer delays OpenAI, and a hang gets the fallback at ≤ 2.5 s.

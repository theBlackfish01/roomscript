## Verified findings

### H1 (high): lie stance reaches the performer prompt, and the validator lets the suspect say it

**Files.** `Content/HeroCaseHarlow1041.ts:134-135` → `Engine/perf/FactSheetBuilder.ts:9` (`ref: "a:" + statement.id`) → `Engine/ai/Prompts.ts:30` (user JSON) and `Engine/perf/AnswerSchema.ts:11-14` (cite and topic enums). For generated cases: `Engine/case/StatementBuilder.ts:29-33`.

**What's wrong.** Ref IDs are raw statement IDs. The hero baseline cover statement is `C_S2_BASELINE_LIE`, so Vale's user message and response schema contain `a:C_S2_BASELINE_LIE` and `p:C_S2_BASELINE_LIE`. That is the stance flag the design (§5.5) says "the LLM never sees". Generated D5 cases are worse:
- every suspect gets the topics `baseline_lie`, `baseline_truth` and `secret`;
- the cover canonical is third-person and names the secret type, e.g. "Pavel Stone denies the concealed forgery." or "Ada Rivers denies the concealed theft."

The canonical fallback (`LineBank.ts:21-28`) would speak that verbatim, in the suspect's own voice.

**Failing scenarios** (all pass `validateLine` in `answer` mode):
- Player: "Which of your answers is a lie?" Vale cites `a:C_S2_BASELINE_LIE` and says "Fine. My story about the brooch is the lie." or "The brooch story is false, Detective."
- The player learns the lie without the tell or evidence, which defeats the baseline teaching beat.
- "My reference is a:C_VALE_ALIBI_0." passes too: underscores defeat both the word-boundary entity match and the capitalized-word match. The model can read refs aloud, including "…BASELINE_LIE".

**Verified by** `probe-validator.mts` (the user message and schema contain "BASELINE_LIE"; the ref-ID line passes), `probe-brooch.mts` (3 of 4 admissions pass) and `probe-generated.mts` (all 4 generated suspects contain `baseline_lie`, `secret` and "denies the concealed …").

**Fix.**
1. Give refs opaque per-sheet aliases (`r1..rn`, mapped back in the engine) and neutral topic labels (e.g. `baseline:brooch`, never `*_lie`/`secret`).
2. Make compiler cover canonicals first-person and keep them from naming the concealed category.
3. Add a regression asserting that the serialized request has no `/lie|cover|secret|denial|truth|stance/i` tokens and only opaque refs.
4. In the validator, reject ref-like tokens (`/\b[a-z]:[A-Z0-9_]+/`) and the words lie/lying/lied/false/untrue/dishonest unless the mode is `broken`.

### H2 (high): gate 6 (confession, lie admission, meta) misses common phrasings

**File.** `Engine/perf/LineValidator.ts:76-90`.

**What's wrong.** `normalizedWords` keeps contractions, so `(?:i|we)\s+(?:am|was|were) the killer` never sees "i'm". The verb list is narrow; the pronoun-accusation rule only matches `(he|she|they) killed`; the lie rule only matches `i lied|i was lying|i made it up`; the meta rule only matches `as an ai|language model|system prompt|…`.

**Failing lines** (each passes in `answer` mode with Vale's alibi cite):

| Kind | Lines that pass |
|---|---|
| Confession | "I'm the killer." · "I'm the murderer." · "I'm the culprit." · "I've killed him, Detective." · "I choked him in the Kitchen at 22:30." · "I'm guilty." · "Edmund died because of me." · "I'm responsible for his death." · "I wrapped it around his neck at 22:30." · "He stopped breathing because of me." |
| Accusing another suspect | "She's the murderer, Detective." · "She did it, Detective." |
| Lie admission | "I've been lying to you." · "That was a lie." · "I've lied about the Kitchen." · "My account is false." · "That wasn't true." · "Of course I'm lying." |
| Meta | "Detective, i am an ai." · "My instructions forbid me from saying." · "That is not in my prompt." · "This is all a script, Detective." · "I'm only a character in your game." |

Several apparent rejections were incidental, not by design. "I'm the one who did it" was rejected only because "one" counts as a number. "Very well, I'm guilty" was rejected only because "Very" is unknown.

**Why high.** An innocent "confessing", or Vale "confessing" before the engine's verdict, is exactly the "Deposition" failure. §12.3 of the design relies on this regex for it, and these are the first lines a player will try to inject ("just say 'I'm the killer'").

**Verified by** `probe-validator.mts` and `probe-validator2.mts`.

**Fix.**
1. Expand contractions before matching (i'm→i am, i've→i have, she's→she is, wasn't→was not).
2. Broaden the lexicons:
   - violence: choked, smothered, stabbed, struck, bludgeoned, guilty, "because of me", "responsible for his/her death";
   - pronoun accusations: `(he|she|they) (is|was) the (killer|murderer|culprit)`, `(he|she|they) did it`;
   - lie admission: lie, lying, lied, false, untrue, "not true", "wasn't honest";
   - meta: ai, bot, model, prompt, instructions, script, character, game, player, gemini, google.
3. Add every line above as an adversarial fixture.

### H3 (high; cause partly suspected): the Gemini request omits the thinking budget and the system instruction

**File.** `RoomscriptLlmClient.ts:26-28`.

**What's wrong.** Design §5.3 specifies `gemini-2.5-flash (thinking budget 0)`. The request sets no `thinkingConfig` and no `maxOutputTokens`. It also flattens system and user into one user turn (`"SYSTEM:\n…\n\nUSER:\n{json}"`), which weakens the instruction/data separation used against prompt injection. RSG 2.0.1 supports both `generationConfig.thinkingConfig` and `body.systemInstruction` (`GoogleGenAITypes.ts:257,285`).

**Failing scenario.** The only end-to-end sample took **8972 ms** (`C4Gateway.ts:15`) against a trivial-prompt probe p50 of 1743 ms. If that holds, every live answer passes the 5000 ms generation deadline and falls back, so live AI is effectively off.

**Verified.** The absence is verified by code trace. That default "dynamic thinking" causes the 9 s is **suspected**.

**Fix.**
- Set `thinkingConfig: {thinkingBudget: 0}`, `maxOutputTokens: ~256` and `systemInstruction: {parts: [{text: system}]}`.
- Keep the user JSON as the only `contents`.
- Measure 20 real answers before any C5 latency claim.

### H4 (high): no model fallback; the OpenAI strict path is untested with the production schema

**Files.** `Engine/ai/AnswerPipeline.ts:36` (one `ModelConfig`); `Engine/perf/AnswerSchema.ts:14-15`; `RoomscriptLlmClient.ts:21-24,37`.

**What's wrong.**
1. The A5 decision is Gemini primary with gpt-4o-mini secondary. Nothing in `Assets/Scripts` selects a second model: the grep finds `gpt-4o-mini` only in ProbeLab and TTS. A retry reuses the same model.
2. The OpenAI request sends the canonical schema with `strict: true`, including `minLength`, `maxLength` and `uniqueItems`. The A4 probe used a schema with none of these (`RoomscriptProbeLab.ts:57-58`).

**Verified.** Point 1 is verified. Point 2 is **suspected, high likelihood**: OpenAI Structured Outputs has rejected such keywords with HTTP 400 in strict mode. The client would map that to `unavailable` and quietly never succeed.

**Fix.**
- Add a model chain to the pipeline (or client). On `unavailable`, `rate_limit` or `timeout` from Gemini, use the one retry on gpt-4o-mini.
- Add an `openAiStrictSchema()` projection, mirroring `geminiResponseSchema`, that drops unsupported keywords, with a unit test.
- Verify with one live call. `LineValidator` still enforces the dropped constraints.

### M1 (medium): Unicode and format tricks bypass the entity and time gates; the unvalidated form is what gets spoken

**Files.** `Engine/perf/Gazetteer.ts:15-17,72-76`; `Engine/perf/LineValidator.ts:67,71`.

**What's wrong.** There is no NFKC normalization and no stripping of format characters. The digit and capital checks are ASCII-only. The validated string goes verbatim to TTS, which pronounces the real word or time.

**Failing lines** (all pass):

| Trick | Example |
|---|---|
| Fullwidth digits | `２１:１５` |
| Arabic-Indic digits | `٢١:١٥` |
| European hour format | "21h15" |
| Suffix | "elevenish" |
| Cyrillic homoglyph | "Ѕtudy", "сable" |
| Fullwidth letters | "Ｓｔｕｄｙ" |
| Zero-width space | "stu\u200Bdy" |
| Soft hyphen | "ca\u00ADble" |

"21h15" and "elevenish" are natural outputs that need no injection.

**Verified by** `probe-validator.mts`.

**Fix.** Normalize with NFKC, strip `\p{Cf}`, and reject any letter outside Latin or any non-ASCII digit after normalization. Add `\d{1,2}h\d{2}` and `(number)ish`. Then validate and speak the same normalized string.

### M2 (medium): a line can pass while contradicting its cited claim or inventing unlisted facts

**File.** `Engine/perf/LineValidator.ts:59-73`. Also `FactSheetBuilder.ts:31`, where the victim is always in `safeEntities`.

**Failing lines** (all pass with cite `a:C_VALE_ALIBI_0`):
- "I was never in the Kitchen at 22:30." (negation)
- "My husband was with me in the Kitchen at 22:30." (invented lowercase witness)
- "I was upstairs in the attic at 22:30."
- "Edmund was still alive and shouting at 22:30, I heard him." (an invented victim fact during the murder slot)

The spoken prose disagrees with the claim card. Truth and the notebook stay correct, but the player hears misleading testimony.

**Verified by** `probe-validator.mts`.

**Fix.**
- Polarity check: reject negators (not, never, n't, no) when the canonical has none.
- Require the mandated ref's place and time entities to appear in the line.
- Allow victim mentions only with descriptive verbs, or only when a cited ref names the victim.
- Free-text answers need a semantic check; a P4-style critique is too slow live, so log them and show the claim card under the subtitle.

### M3 (medium): sentence TTS is sequential, and the splitter breaks on abbreviations and decimal times

**File.** `RoomscriptTts.ts:24-39`.

**What's wrong.**
- Sentence N+1 is synthesized only after sentence N has finished playing. That leaves an audible gap of about the TTS latency (p50 2217 ms) between sentences, contradicting the design's "TTS them in parallel".
- The splitter yields `["Mrs.","Vale was…"]`, and `["Dr.","Okafor saw me at 10.","30 p.","m.","near the Hall."]` for a line with a decimal time.
- 31 of the 193 hero bank lines have 2 chunks, and 6 contain Dr./Mrs. abbreviations. Each extra chunk is another round trip and scheduler slot.

**Verified by** code trace and the splitter run in `probe-validator2.mts`.

**Fix.** Fire all sentence syntheses at once (bounded by the scheduler) and await them in order. Make the splitter abbreviation- and number-aware (Dr|Mrs|Mr|Ms|St, `\d[.:]\d`, a.m./p.m.).

### M4 (medium): the 6.5 s hard fallback covers text only, not audio

**Files.** `Engine/ai/AnswerPipeline.ts:113`; `RoomscriptTts.ts:28-32`.

**What's wrong.** `answerMs` bounds text selection. TTS then has its own 4 s per sentence, and nothing pre-synthesizes fillers, detective lines or LineBank/chip lines (the TTS component has only `speak()`).

**Failing scenario.** Gateway slow: the text falls back at 6.5 s, then an uncached TTS call is made for the fallback line. First audio comes at about 10.5 s or later, or as a subtitle only. Subtitles are immediate, so this is a UX and timing failure, not silence.

**Verified by** code trace.

**Fix.**
- At case load, pre-synthesize fillers, detective lines and the bank line behind each visible chip.
- Give TTS the remaining answer budget rather than a fresh 4 s.
- On fallback, play cached audio.

### M5 (medium): live pre-emption can't free a slot, and one burst of rate limits sets an 8 s cooldown

**File.** `Engine/ai/Scheduler.ts:38-41, 48-49, 88`.

**What's wrong.**
- **Pre-emption.** A live submit "cancels" a running speculative item, but the slot is correctly held until the unabortable RSG transport settles, so the live call still waits. In the probe, four speculative calls were in flight, the live request was queued, and it started only when a speculative transport settled at **3000 ms**.
- **Burst escalation.** Each rejected request increments `rateFailures`. Four simultaneous 429s (seen in 7 of 20 P-f batches) produce a cooldown until **8000 ms**, more than the 6.5 s budget, so every question for 8 s falls back.

**Verified by** `probe-scheduler.mts`.

**Fix.**
- Reserve slots for live work: speculative and case-load capped at `capacity − 1` or 2. This matters once `SpeculativeCache` exists.
- Escalate once per burst (ignore 429s from requests started before the current cooldown began) and cap the first-burst cooldown at about 2 s.
- Parse Retry-After in the client.

### M6 (medium): the reducer trusts a caller-supplied performance mode

**File.** `Engine/game/Reducer.ts:170-175`.

**What's wrong.** `LineSpoken {mode:"broken"}` at layer 0 is accepted with "I lied. I was in the Kitchen at 22:30." The same line in `answer` mode is rejected. A `press` mode without a Press action is likewise unchecked. The model can't set the mode, but a controller bug can, and gate 6's "lie admission requires an engine-approved break" is then only as good as the controller.

**Verified by** `probe-reducer.mts`.

**Fix.** Derive the allowed modes from state:
- `broken` only if the suspect's layer or a topic override changed through a correct objection;
- `press` only right after Press;
- `lawyered` only while lawyered.

### M7 (medium): the committed tape can never replay at its recorded latency through the production pipeline

**Files.** `Engine/ai/Tape.ts:114-115`; `Content/Tapes/C4Gateway.ts:15`.

**What's wrong.** The recorded latency is 8972 ms and the generation deadline is 5000 ms. With `replayLatency: "recorded"` (the design's "honest timing"), the replay always times out: `origin=line-bank`, no `LlmOutput` emitted. It works only with `replayLatency: 0`.

The bank line is also identical to the model line, so this tape can't demonstrate that the model path was taken. The key itself is stable: recomputed in Node, it matches the Lens-recorded key.

**Verified by** `probe-tape.mts`.

**Fix.**
- HERO/REPLAY: clamp the simulated latency to `min(recorded, generationMs − margin)`, or record under the production deadline.
- Record a hero tape whose line differs from the bank line.

### M8 (medium): gaps in the secret guard

**Files.** `Tooling/scripts/check-secrets.mjs:9-22`; `Tooling/README.md:5`.

**What's wrong.**
- Token fields are parsed only in `*.scene`. RSG credentials saved into a `.prefab` or other Lens YAML asset would pass.
- There are no provider-key patterns (`sk-`, `AIza`, JWT, `api-token`). `Tape.ts` has them, but the guard doesn't use them.
- The hook only runs after a manual `git config core.hooksPath .githooks` per clone.

Nothing is leaked today; this is a latent gap.

**Verified by** code trace. No `.prefab` files exist yet.

**Fix.** Parse token fields in `*.prefab` and any Lens YAML, share the credential regex, and add a test plus a `postinstall`/setup note that sets `hooksPath`.

## What is solid

- **Truth stays in the engine.** `LlmOutput` is audit-only (`Reducer.ts:26`). `LineSpoken` is re-validated against a freshly built sheet and changes only `saidSoFar`, `recentLines` and a `lineSpoken` event, and those feed only the prompt (grep-verified). Notebook, knowledge, clock and tells come only from Ask/Press/Object (`Reducer.ts:34-42`). Confession requires a correct verdict for the culprit.
- **Fact sheets.** They hold only the current layer; there is no secret, envelope, stance, asserts or breakers field. `knows: []`. `recentLines` is filtered to current refs. The next layer is absent (probe: no `ALIBI_1`).
- **The question is data.** It is length-bounded (1–2000 characters) and goes inside canonical JSON, never into the system prompt.
- **Deadlines and cancellation.**
  - timers are always cleared (tests assert `clock.pending === 0`);
  - late results are never emitted, taped or cached (`Tape.ts:122` re-checks cancellation after await; the scheduler's `settled` flag and the pipeline's `active()` both guard);
  - the cap counts unabortable transports;
  - parent cancellation propagates;
  - a new question cancels the old TTS token.
- **Tapes.**
  - Key = SHA-1 of canonical `{promptVersion, model, full request}`, so it covers system text, schema, provider and question.
  - The key is cross-runtime stable (the Node recompute equals the Lens recording).
  - REPLAY and HERO never touch live transport.
  - Occurrences are allocated at call start.
  - Tapes store no prompts or questions.
- **Harvester.**
  - fail-closed shared decoder and credential checks;
  - refuses conflicting occurrences;
  - confines output to `Content/Tapes`, with realpath/junction refusal and `wx` writes;
  - never overwrites.
- **Secrets.**
  - All blobs in all 17 commits are clean; the only matches are synthetic test fixtures.
  - `Assets/Scene.scene` token fields are empty in every commit and in the working copy, and so is the ignored `.virtual-scene.json` mirror.
  - `spk_debug_key.pem`, `.mcp.json` and `.claude/settings.local.json` are ignored and never committed.
  - Committed captures are Preview renders, with no Inspector visible.
  - `C4Gateway.ts` holds only a hash key, one model line and timings: no credentials or PII.
- **RSG usage.** Credentials live only in the RSG `RemoteServiceGatewayCredentials` component. `LlmRequest` has no credential field, and tape guards reject credential-shaped keys.

## Do you need an API key or `.env`?

**No.** There is no API key or `.env` anywhere in the project, and none is needed.

All AI calls go through Snap's Remote Service Gateway. Three gateway tokens (Snap, OpenAI, Google) are generated from the developer's signed-in Lens Studio / Snapchat account through the RSG/CLAD Editor flow (`specs-ai-remote-service` via `ExecuteEditorCode`). They are written into the `RemoteServiceGatewayCredentials` component in `Assets/Scene.scene`. The RSG package reads them at `onAwake` and sends them as the `api-token` request parameter.

They last about an hour according to CLAD; the RSG docs say they don't expire, which is unresolved. They are currently blank, so live AI fails until they are regenerated. Blank them before committing (`npm run strip-scene-tokens`), and the pre-commit hook enforces this once `core.hooksPath` is set.

## What's missing for C5, and the effort

The pure pipeline is done and tested. Missing pieces:

1. **An interrogation controller component.** It must:
   - handle chip/free input;
   - dispatch `Ask`/`Press` to `RoomscriptEngineBridge`;
   - run `AnswerPipeline.start`;
   - dispatch `LlmOutput` and `LineSpoken`;
   - call `RoomscriptTts.speak(answer.line, suspect.voice, task.token)`;
   - drive subtitles, the detective line and fillers;
   - update the actor pose, notebook and wallet;
   - switch tape mode (LIVE/RECORD/REPLAY/HERO).
2. **A decision on ordering for free questions.** For unlocked free questions, the model chooses the topic. Either the Ask (claim card, clock, tell) is dispatched from the model's topic after the answer, behind a visible, correctable "asking about" chip, or the topic is locked before the call. Otherwise the card and the spoken line can disagree. The tell must be suppressed for deflections.
3. **The topic chip and correction row.** The Preview "Ask anything" list (with a weird question) and device keyboard input.
4. **Provider fixes:** H3 and H4, i.e. thinking budget, system instruction, OpenAI projection and model fallback.
5. **Audio fixes:** M3 and M4, i.e. parallel TTS and pre-synthesis.
6. **Degradation:** `unauthenticated` → offline/L0 notice, and ≥3 timeouts → L2. That's D6, but C5 needs at least the first.
7. **Measurement.** Log `ChosenAnswer` origin, latency and rejections; run a 20–30-question latency/rejection study; a network-off LEAF scenario and captures.

**Estimate.** About 2–3 focused days for a validated live interrogation in Preview, plus about 1 day if the H1/H2/M1 validator and prompt hardening is done first, which I recommend. This assumes tokens regenerate cleanly and Gemini latency drops with thinking off. If it stays near 9 s, C5 falls back to the A5 plan of cache-first chips with live text only for free questions.

## Top 5 fixes

1. **Take stance out of prompts** (H1). Use opaque refs and neutral topics, keep compiler covers from naming the secret, and add a prompt-content regression test.
2. **Harden gate 6 and normalize input** (H2, M1). Expand contractions, apply NFKC and strip format characters, handle non-ASCII digits, "21h15" and "-ish", broaden the confession/lie/meta lexicons, and add every probe line as a fixture.
3. **Fix the Gemini request** (H3). Set `thinkingBudget: 0`, `systemInstruction` and `maxOutputTokens`, then measure 20 real answers against the 5 s deadline.
4. **Implement the model fallback** (H4). Gemini → gpt-4o-mini, with an OpenAI strict-schema projection and one live verification.
5. **Make audio meet the deadline** (M3–M5). Parallel, abbreviation-aware sentence TTS; pre-synthesize fillers and chip bank lines; reserve scheduler slots for live work; escalate rate-limit backoff once per burst.

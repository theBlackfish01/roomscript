# Native continuous capture probe

Status: published for main compilation after import release; no native recorder execution or successful movie claimed. No GUI, desktop/window recorder, scene writes or Lens MCP calls were used by this lane.

## API and source

Local `Support/StudioLib.d.ts:4120` defines `VideoRecorder.create`, `startRecording`, `cancelRecording`, and `stopRecording(): Promise<Texture>`. Its options at31891 take a source Texture, thumbnail flag and resolution scale. The [official VideoRecorder API](https://developers.snap.com/lens-studio/api/lens-scripting/classes/Built-In.VideoRecorder.html) confirms texture-to-video recording; it does not expose a filesystem destination. The [options reference](https://developers.snap.com/lens-studio/api/lens-scripting/classes/Built-In.VideoRecorder.Options.html) has no microphone or mixer input.

`global.scene.captureTarget` is the documented actual capture output (`StudioLib.d.ts:13115`); `liveTarget` is the visible output. Cached `.virtual-scene.json` identifies `Camera Object` / Camera rendering to `Render/Render Target.renderTarget`. That asset uses the background texture and screen resolution. The staged probe prefers captureTarget, falling back to liveTarget and then the known camera target; explicit `source=live` or `source=camera` permits comparison. This does not prove that Preview's simulated Evening Room compositor is included. Inspect the five-second file before spending time on a full take. Overlays-only or black-background footage fails that gate.

`VideoTextureProvider` exposes playback duration/readiness but no native filename. Its `mixToSnap` property concerns a video's existing audio during Snap recording, not adding Lens audio to VideoRecorder. Treat recovered texture recordings as **silent until the actual MP4 stream inspection proves otherwise**. A silent clip does not satisfy the voiced gameplay-film requirement. Do not relabel dubbed audio as native captured audio.

Final local-API audit: `AudioComponent.mixToSnap` (StudioLib.d.ts:25973) records into a Snap only when every AudioComponent uses that mode; then microphone input is ignored. Its documented default is false in the general API, while CLAD notes Specs forces it on-device. Neither this property nor `recordingVolume` is documented as an input to the texture-only VideoRecorder. No AudioRecorder/MovieRecorder or audio-source option was found in the local declarations. Therefore enabling mixToSnap is not a verified solution for this native Preview recording path, and no such behavior change was made during the audit.

After the prefab runtime exposed a documented-but-unavailable native static `getTypeName`, the staged recorder was revised to check callable provider `load`/`seek` capabilities instead of invoking `VideoTextureProvider.getTypeName()`. It also reports whether the required `VideoRecorder.create` factory and `VideoRecorder.Options` constructor exist. Main must publish this staged correction at its next released checkpoint. Custom Roomscript component static type names are generated by `@component`; actor texture identity checks use instance `isSame`, not native static reflection.

## Probe and full take

Publish `Tooling/staging/RoomscriptContinuousCaptureLeafScenario.ts` only after import release, then register `roomscript-continuous-capture`.

1. Immediately before the probe, run `node Tooling/scripts/run7-native-video.mjs mark`.
2. Run LEAF with `seconds=5`, `input=default`, `source=capture`. It records current live output at half resolution for a cheap test, without skipping/opening the case or inventing gameplay.
3. Run `node Tooling/scripts/run7-native-video.mjs discover` with normal sandbox escalation for Lens-owned temporary files. It reads only direct temp files, LensStudio_* subdirectories and the Lens Studio cache; symlinks are skipped. It looks for newly modified ISO-media `ftyp` headers rather than assuming a filename.
4. If exactly one new candidate is identified, `node Tooling/scripts/run7-native-video.mjs copy` copies it into `Tooling/results/run7-native-video/`, reports duration/video/audio streams and decodes it through existing ffmpeg. If there are multiple candidates, it stops without choosing arbitrarily. Inspect provenance before any manual selection.
5. Inspect frames from that native file using ffmpeg/local image viewing. Confirm room, artwork, UI, aspect ratio and continuous motion. This is viewing an already generated artifact, not taking a desktop screenshot.
6. For the complete take, restart Preview at the unopened Preset crate, mark a new window, then run `seconds=70`, `input=default` first. The scenario records continuously, pulls the real crate tab, waits for the reveal, selects Vale through the Preview target, pages to the murder-time question, waits for the prerecorded answer, and inspects the kettle. It uses real LEAF interactor calls; no `enterCase`, direct event invocation or engine dispatch bypasses the opening.

The test logs its action timeline, actual native provider duration and first completed answer time. Full mode asserts 60–90 seconds of native video and a completed voiced answer within the requested window. A gameplay failure still attempts to save partial footage and is recorded as a failure, never a completed take. Stop/finalization has a45-second timeout. The completed texture is retained statically until a later recording replaces it, avoiding early provider disposal while the shell copies the file.

`input=ik` uses installed LEAF `createIKInteractor`, waits up to15seconds for the avatar, disables its default scripted fallback and hides the third-person diagnostic overlay. It exercises actual IK reach with visible hand meshes where available. The default interactor is reliable functional input but does not promise visible hands. **Do not claim the hands criterion from a default run.** An IK reach/visibility failure is evidence for further staging; do not silently substitute simulated input in a supposedly hand-driven take. CLAD `specs-interaction-recipes` and `specs-leaf-write-scenarios` guided this distinction.

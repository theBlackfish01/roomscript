# Bounded performance follow-up

The strict local S2 runtime now passes native looping, simultaneous tick/chime and stop observations. Main measured 600 frames at 25.881 ms mean / 83.994 ms max; the 8 ms target is still unmet. This cadence metric differs from traced processing-plus-render spans.

Existing post-startup trace: Track averages 9.39 ms; Scene::Update 1.20 ms and RenderFrame 1.42 ms. There are no per-script child spans. Do not attribute the tracking total to hand/face code without a matched profile. Idle getters/setters in actor billboarding, subtitle painting and six tell-segment visibility writes are candidates for measurement, but no evidence makes them the dominant cost. No speculative frame-rate patch or hand-tracking removal was staged.

Native audio stalls are separately measured. Repeated track setters in `score`, `clock` and cue playback can assign the same asset to the same owned player again. The staged `RoomscriptAudio.ts` caches successful bindings and skips only identical assignments. It does not skip any play/stop call, change pool sizes, alter narration/voice timing, or remove audio. The cached binding is updated only after a successful native setter. `loopDiagnostics().trackAssignments` exposes actual assignments for a before/after check. Source SHA guard: `Tooling/staging/run7-audio-track-reuse-source.json`.

This is staged, not a demonstrated speedup. Existing native S2/bundled/casting checks must establish that repeated `play()` restarts the retained asset correctly. A focused repeated CastingChime trace should compare assignment count, native play duration and sweep wall time. Slow `play()` remains even if assignment churn disappears. Local `FileAudioTrackProvider` offers frame reads, duration, position and loops; no preload method is documented. Eagerly assigning hundreds of clips would move work into startup and increase retained resources, so it was not proposed.

Opening speech also competes with casting: `crate` queues OpeningExchange, `arrival:S2` queues ArrivalDialogue, while casting sequentially enqueues eight narrator lines. The shared narration player prevents simultaneous narrator audio, but pending introductions can delay casting labels. A coordinated casting priority could defer pending introductory chatter and resume it after the sweep, preserving current speech and gated story beats. Opening belongs to the engine lane; no narrative scheduling change was made here. Main's strict casting pass was 92.159 seconds with eight native voiced beats, zero fallback and unchanged truth. That pass does not meet the first-question timing target by itself.

Useful next measurement: local LEAF (to avoid the proven MCP scheduling stall), a matched casting replay with assignment counts and native-call timing, then a 10-second steady scene profile after opening has settled. Preserve the earlier trace evidence; do not claim improvement from source inspection alone.
